# Building PWA UI

## Overview

`apps/pwa` is Angular 22, zoneless, with OnPush and standalone as defaults. Never set either explicitly. Its layers:

| Layer                                     | Holds                                                                                                                                                                                                     | May import                                                                                                                                                                                                  |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `core/api`                                | `DataApi`, `AuthApi`, `wire.ts`; the only importer of `src/generated`                                                                                                                                     | generated client, `@asys/domain`                                                                                                                                                                            |
| `core/auth`, `core/data`, `core/platform` | session, `DataStore`, `TimeZoneSync`, `CommandAttempts`, the shell-provided `DoneUndo` and `CaptureQueue`, `ReportedZone`, seams (`Clock`, `Ids`, `DeviceStorage`, `Motion`, `Haptics`, `TaskMorph`, ...) | `core/*`, `@asys/domain`                                                                                                                                                                                    |
| `pages/<screen>/`                         | routed screens: inject services and render exactly one template, with no HTML or CSS file; a screen's pure helpers and route wrapper sit beside it                                                        | `core`, `@asys/domain`, one `components/templates/` component, `components/support/`                                                                                                                        |
| `layout/`                                 | the shell, outside the Atomic Design levels: outlet, quick add, Undo bar, bottom nav (and `app.ts`)                                                                                                       | `core`, `components/` except `components/templates/`; never `pages/`                                                                                                                                        |
| `components/<level>/<name>/`              | the Atomic Design levels (`components/README.md`); atoms, molecules, organisms and templates; `components/atoms/icon` alone imports Font Awesome                                                          | `@angular/*`, `@asys/domain`, its own level or below, as `scripts/check-architecture.mts` checks; `components/organisms/swipe-actions` alone also the `core/platform` seams `Motion`, `Haptics` and `theme` |

Lint bans runtime imports of `@asys/contract`, `effect` and `@ionaru/effect-passkeys/api` (type-only is fine). `@ionaru/effect-passkeys/server` and `/testing` are banned outright. `@ionaru/effect-passkeys/client` is the one passkeys entry the PWA may use at runtime.

## Component conventions

- Use signals throughout: `input()`, `output()`, `model()`, `viewChild()`, and `inject()` fields. Never `@Input`, `@Output`, `NgModule` or `ngModel`.
- A member only the class uses is an ES private `#` field (`readonly #api = inject(DataApi)`). A member the template reads is `protected`, and a signal query is `private`, because Angular refuses a `#` name for either.
- Write templates and styles inline until the component's `.ts` file reaches 100 lines, then move them to `<name>.component.html` and `<name>.css` as the `angular-component-files` rule (`.agents/rules/`) says.
- Components follow the design system's Atomic Design levels (atoms, molecules, organisms; its README has the table), and a component holds only parts of its own level or below. `components/README.md` has the rules and the decisions where the code departs from the design system, and `node scripts/check-architecture.mts` checks every import under `components/`, `pages/` and the shell (`layout/`, `app.ts`) against them. Build fields from the atoms: `label[asys-label]` (`components/atoms/label`, also on a `legend` or the `span` that names a group), `[asys-input]` (`components/atoms/input`, on an `input`, `textarea` or `select`, with `InputVariant.Title` for a Task title edited in place and `InputVariant.Grow` for Notes) and `asys-input-box` with `asys-single-line` (below). Never write their classes by hand.
- A link that goes to another screen from text or a list is `a[asys-link]` (`components/atoms/link`), with `[block]="true"` on a line of its own, which gives it the tap target and the Voice only height. A Button acts, a Link goes. A whole-row link (the Settings and Areas lists, the top pick's title, the bottom nav) keeps its own class.
- Two or three Buttons side by side go in `div[asys-button-group]` (`components/molecules/button-group`), with `[fill]="true"` when they share a card's row in equal widths. Never write the `asys-button-group` classes by hand.
- A choice that stays pressed is `button[asys-segment]` (`components/atoms/segment`) with `[pressed]`, `[num]` and `[stacked]`. The consumer binds `[disabled]` and `(click)` natively and writes only the `asys-segment__value` and `__unit` spans of a stacked num Segment by hand.
- Forms use Signal Forms (`@angular/forms/signals`), and shared controls implement `FormValueControl<T>` (`components/molecules/text-field`, `components/molecules/segmented-control`). `asys-segmented-control` takes `legend`, `options` (`SegmentOption<T>[]`, each `{ value, label }`) and `layout` (`SegmentedControlLayout`); Importance passes `IMPORTANCE_OPTIONS` from `components/support/importance-options.ts` with the Fill layout. They extend `FieldControl` (`components/support/field-control`), which holds `hint`, `errors`, `touched`, `disabled`, `touch` and the error and hint ids.
- A one-line text field is a one-row textarea, never `<input type="text">`: Chrome on Android shows its passwords, cards and addresses bar above the keyboard on every text input, whatever its `autocomplete`, and never on a textarea.
  - `asys-text-field` does this itself. Pass `[autofill]="true"` only where the browser's autofill helps, as on the sign-up Name and the Recovery code.
  - A field that is not a TextField (the Estimate's Other minutes) builds from the atoms instead: an `asys-input-box` (`components/atoms/input/input-box`, which focuses the field on a press beside it) around a `textarea` with `asys-single-line` (`components/atoms/input/single-line`). The directive sets `rows="1"`, turns pasted line breaks into spaces before it emits `(lineChange)` with the value, and on Enter or a phone keyboard's line break emits `(lineBreak)` and submits the form implicitly, unless `[submitOnEnter]="false"`, as on the Task editor's Title, which has no box. Bind `(lineChange)`, never `(input)`, so a handler always sees the flattened value. Capture is the `asys-capture-field` molecule (`components/molecules/capture-field`), a pill box with Add and a hint.
  - A template event handler never returns `false`: Angular then prevents the event's default, which swallows typing and Escape.
- Derive Task state on screen (Blocked, Overdue, Available, the reason line) from the `@asys/domain` rules, such as `blockedReasons`, `isBlocked`, `isOverdue` and `explainTask`, so a `RULES_VERSION` change reaches every screen.
- **Components** (`components/`):
  - Use the selector `asys-<name>` and `ViewEncapsulation.None`.
  - The host class has the `asys-` prefix, with BEM elements and `--modifier` classes. Bind them in `host: {}` (see `components/atoms/quadrant-label`).
  - Closed sets are exported `enum`s, exposed to the template as `protected readonly Variant = ButtonVariant`.
- **Features** keep the default encapsulation, with classes such as `now__title`.
- **Styling:**
  - Use token CSS variables only (`--paper`, `--ink`, `--signal`, `--space-1` to `--space-7`, `--tap-target`, `--font-size-*`), never hex colours.
  - Add a `[data-theme='drive']` rule when tap size must differ in Voice only. The theme sits on `<html>`, so an emulated stylesheet writes it as `:host-context([data-theme='drive']) .x`, while a `ViewEncapsulation.None` component such as `components/atoms/link` writes `[data-theme='drive'] &`. Motion needs none: the kill switches in `src/styles.css` and `Motion.allowed()` already turn it off there and under reduced motion.
  - Timings come only from the motion tokens `--duration-quick`, `--duration-moderate`, `--ease-out`, `--ease-in` and `--ease-emphasized`. Never write a literal `ms` value or curve.
  - Script motion goes through `Motion.play` with `MotionDuration` and `MotionEasing`, and a haptic through `Haptics.tick()`. Never call `animate` or `navigator.vibrate` directly; jsdom has neither. `play` never rejects (it reports a failure other than a cancel with `console.error`), so a caller adds no `catch`.
  - View-transition CSS (names, the z-index ladder, keyframes) lives only in `src/styles.css`. The ladder is `page` auto, `task-title` 1, `shell-capture`, `shell-undo` and `shell-nav` 2, `nav-mark` 3, and `nav-glyph-1` to `nav-glyph-3` and `nav-badge` 4. New fixed shell chrome gets a name and a rung, or the sliding page paints over it. Anything drawn inside the moving `nav-mark` pill gets a name of its own on the top rung, or it travels with the pill.
  - `data-task-id` is the morph hook that view transitions match, so a form control may carry it (the Task editor's Title). A Task title that the shell may focus, after an Undo or on Escape in the Undo bar, carries `data-focus-title` as well, as `components/molecules/task-row` and `components/organisms/top-pick` do; the shell never focuses an element without it.
  - Put a style in `src/styles.css` only when several controls share it.
  - Reuse the shared classes in `src/styles.css` instead of copying their rules, and keep the feature class (such as `now__status`) on the element as the hook that specs query. Next to `asys-page` are `asys-page__title` (the margin under a screen's `h1`, which is `[asys-text]` with `TextStyle.Title`, with `asys-page__title--flush` when the screen spaces its blocks with a gap), `asys-page__status` (the margin of the status line under it, a `p[asys-text]` in Body, which takes no room while empty), `asys-fieldset-reset` (a fieldset without the browser's border, padding and margin) and `asys-field-row` (the FieldRow molecule's row, `button[asys-field-row]` in `components/molecules/field-row`, with `__label`, `__value`, `__value--set` once something is chosen, and `__chevron`; Voice only makes it taller; a sheet's option rows reuse the class). A number of things is the Count atom, `<span asys-count [value] [variant]>` (`components/atoms/count`), never a hand-written pill.
  - Text that stands on its own (an empty state, a note, a message, a heading in a template) is `[asys-text]` (`components/atoms/text`) with a `TextStyle` picked by role (a reason is always `Reason`), and its own class keeps only margin and colour; never a literal `font-size` and `line-height` pair. A component's own parts keep their own rules. Read a Text host in `viewChild` with `{ read: ElementRef }`.
  - `asys-num` sets the mono font and tabular figures. A component rule on the same element that sets `font-family` beats it (equal specificity, and component styles load after `styles.css`), so leave `font-family` out of that rule.
  - The shared enter classes there are `asys-rise` (a small rise and fade, for bars), `asys-appear` (a fade) and `asys-pop` (a badge pop), used with `animate.enter`. A node that leaves with motion uses the function form `(animate.leave)` with `leaveMarked` (`layout/shell-motion.ts`) or `collapseRow` (`pages/now/row-motion.ts`), thin calls to `Motion.leave`, which sets `data-leaving` first, so a view transition never sees the leaving node beside its replacement, and then calls `animationComplete` once.
- **CSS nesting:**
  - Nest a rule inside the existing rule whose whole selector it already contains, so flattening gives back the original selector: a state or part of the same element (`&:hover`, `&::after`, `&[aria-pressed='true']`, `a&`), a descendant or child (`& .asys-icon`, `& > span`) or a context (`[data-theme='drive'] &`, `.task-editor__rows + &`). Always write `&`, and nest only into a rule with declarations of its own. Each BEM element and modifier keeps a top-level rule of its own, which can be a parent in turn (`.asys-button--large { & .asys-icon { ... } }`).
  - An emulated stylesheet (any component without `ViewEncapsulation.None`: today `components/templates/`, `components/organisms/task-blockers`, `layout/` and `app`) nests only descendants, children, contexts and at-rules: each `&` stands alone between combinators or spaces (`& > li`, `.ctx &`), and the parent is one selector. `:host`, `:host(...)` and `:host-context(...)` rules neither nest nor take nested rules. Emulated scoping adds the content attribute to every compound, so once nesting reaches it unflattened, a compound `&` under `:host` loses the host attribute and any other compound `&` gains specificity. For the same reason a context outside the component, such as the theme on `<html>`, matches only through `:host-context(...)`, flat or nested.
  - Nest `@media`, `@supports`, `@container` and `@starting-style` inside the rule they modify. `@keyframes`, `@font-face` and `@property` stay top-level, and so do the view-transition and motion kill-switch sections of `src/styles.css`.
  - Keep the cascade order: nest a rule only when it already sits next to its parent, or when every rule between them folds into the same parent in the same order. Any other rule stays flat where it is, even where moving it looks harmless.
  - A parent is one selector, or a list whose members share one specificity, and never a pseudo-element. A context (`.ctx &`) needs a parent of one compound selector. A shared selector list stays whole. `&` goes inside `:where()` only (`:where(& button)` keeps zero specificity).
  - Declarations come before nested rules, because flattening hoists them. A blank line separates sibling rules at every depth and precedes the first nested rule (oxfmt never adds one), and a comment moves with its rule.
  - Today the build flattens all of it: Angular always lowers nesting in component styles (`supported: { nesting: false }`, angular/angular#58996), and `src/styles.css` follows the browser targets, so it reaches the browser nested first, once Angular's baseline passes Chrome 120 and Safari 17.2; the rules above keep native nesting equal to the flattened form. `src/app/css-nesting.spec.ts` fails once component nesting reaches the browser unflattened. From then on the emulated limits are load-bearing, and specs that read computed styles of nested rules break, because jsdom applies only top-level rules and `@media`.
- **Icons:** draw them with `<asys-icon [name]="IconName.X" />` (`components/atoms/icon`), or a Button's `icon` input. `IconName` is the closed set of Font Awesome Pro Classic Regular names the design system's Icon table lists (Solid only for the current tab); add a name there, with its import, when a screen needs a new one. Icons are 1em tall and take the text colour, so size them with `font-size` in `em`, never px. Never import `@fortawesome/*` outside `components/atoms/icon`, and never copy Pro SVG data into the repository.
- **Swipe** (`components/organisms/swipe-actions`): `<asys-swipe-actions [taskId] [disabled] [endEnabled] [startEnabled] (commitEnd) (commitStart)>` wraps a Task's content. A right swipe emits `commitEnd`, a left one `commitStart`, each with the Task id recorded at `pointerdown`, and nothing when the input has changed since. Use it only on Now's top pick and ranked rows, wrapped inside the `<li>` so the row selectors hold, and only where every swipe action has a single-pointer control elsewhere (WCAG 2.5.1 and 2.5.7): the top pick's buttons, the editor behind a row's link. Touch and pen only; Voice only, a mouse, a form control and the screen edges never swipe. The tuning constants live in `swipe-decision.ts`. Pointer listeners use `addEventListener` and write the surface's `translate` straight to the DOM, so a move runs no change detection. Its specs stub `getBoundingClientRect` on the host instance (never the prototype) and `performance.now`, and dispatch `PointerEvent`s with `isPrimary: true`.
- **Sheets** (`components/organisms/sheet`): `<asys-sheet [heading] [(open)]>` around one `<ng-template>` body, which renders only while open. `asys-choice-row` (a choice from a list) and `asys-date-row` (a date with a split time button) are the Signal Forms row controls that open sheets. It is a native `<dialog closedby="any" autofocus>` opened with `showModal()`, so the focus trap, Escape, a tap on the backdrop, the top layer above the shell's fixed bars and focus back on the opener come from the browser, and the dialog itself takes focus, so a sheet holding a text field does not raise the phone keyboard. Place the sheet outside its opener's `@if`, so closing it never destroys the body mid-exit. jsdom has no `showModal` or `close`: `src/test-setup.ts` (the test target's `setupFiles`) gives them an `open` state and a synchronous `close` event, so unit specs check the open state and the Close button, and Escape, the backdrop and focus return are e2e checks.
- **Accessibility:**
  - Errors read "Error:" with `aria-invalid` and `aria-describedby`, never colour alone.
  - Quadrants differ in lightness or form, never hue alone.
  - A clipping wrapper (`overflow: clip`) keeps the focus ring with `overflow-clip-margin: 4px`, and when its content is positioned it lifts itself with `:focus-within`, so the next row does not cover the ring. `components/organisms/swipe-actions` makes each host its own stacking context (`z-index: 0`) and lifts the focused one to 1, so its inner layers never rise over the shell's fixed bars.
  - The bottom bar holds the three destinations and, on the tabs, the Capture button at its end. Its height grows with Text size, so the shell measures it with a `ResizeObserver` and publishes it as `--shell-nav-height` (the CSS default, `tap-target-large` plus its padding and line, only covers the first frame). The Undo bar sits on the nav, and the shell publishes its height as `--shell-undo-height` the same way. The page padding and quick add read both; never repeat a bar height as a literal.

## Recipes

**UI component:**

1. Create `components/<level>/<name>/<name>.ts` and `<name>.spec.ts`, at the level the design system's table gives it. There is no barrel and nothing to register.
2. Model it on `quadrant-label` (display), `button` (attribute selector), `input` (an atom on a native element) or `text-field` (form control).
3. Write the spec with a `Host` component that drives signals, and await `fixture.whenStable()`.

**Screen and route:**

1. Create the page `pages/<name>/<name>.ts` and its spec, with `providers: [CommandAttempts]` when it sends Commands, and its template `components/templates/<name>-template/<name>-template.ts`, which takes the data as inputs and reports actions as outputs (see `pages/area-list`). The page keeps the screen's selector and the template is `asys-<name>-template`. A Signal Forms form stays in the page with its validation and submission, and the page passes its `FieldTree` to the template as an input (see `pages/recover`). Focus that follows the template's own markup, such as the heading on a new step, lives in the template (see `components/templates/sign-up-template`). When the page decides that focus should move, it calls a public `focus…()` method on the template through `viewChild` (see `pages/capture`). A value the page may put back after a failed send, such as a select that follows the store, is a `model()` on the template, bound with `[(…)]` beside the page's own `(…Change)` handler (see `pages/settings`).
2. A screen that reads `DataStore.state()` shows `<asys-load-state>` (`components/molecules/load-state`) while there is none. The template holds it, and the page binds its inputs and outputs to `dataStore.state() !== null`, `dataStore.status() === SyncStatus.Failed` and `dataStore.refresh()`.
3. Add the route in `app.routes.ts`: `loadComponent` and `title: '<Name> · ASYS'`, under `ShellLayout` with `data: { level }` unless it is an auth screen. A full-screen screen with its own top bar and footer (the Task editor) adds `hideNav: true`: the shell drops the bottom nav and the page's top padding, and the screen's sticky footer sits at `bottom: calc(var(--shell-undo-height) + env(safe-area-inset-bottom))`. Its Back button is then the only way out, so render it in every state. The level is 0 for a tab or a screen of its own, otherwise one more than the screen it opens from. `app.routes.spec.ts` fails without it, and the level decides Push, Pop or Swap.
4. Add the title row to `app.routes.spec.ts`.
5. For a primary tab, update `components/organisms/bottom-nav` and `TAB_PATHS` in `core/platform/tabs.ts`: it gives view transitions the tab order and shows Capture on the tabs, and `shell-layout.spec.ts` fails when it and the bottom nav disagree. For an auth screen, add the path to `SIGNED_OUT_PATHS` in `core/auth/safe-return-url.ts`, which the sign-out redirect in `app.ts` also reads, with a case in its spec. Use `signedOutGuard` on the route. A screen shown just after sign-in (like `recovered`) goes in that file's `AUTH_PATHS` instead, without `signedOutGuard`.
6. An id-keyed editor gets a `<name>-route.ts` wrapper (see `task-editor-route.ts`). Its `@for (id of [id()]; track id)` builds the new editor before it destroys the old one, so state an editor publishes outside its host (a class or custom property on `documentElement`, a global listener) is counted per instance and removed with the last one, as `chromeEditors` in `task-editor.ts` is. An editor that follows the store while the person edits uses `followStore` and `settleSaved` from `core/data/draft-follow.ts`. The Task editor has no Save button: `pages/task-editor/task-draft-saver.ts` saves each change as it happens, taps at once and typed text once committed, with a flush before Done and on leaving. Read its doc comments before changing when anything saves.
7. Add an e2e spec for the user-facing flow (`writing-e2e-specs`).

**Calling a new endpoint or Command:**

1. Run `pnpm exec nx run pwa:api-client`.
2. Add a method in `core/api/data-api.ts` or `auth-api.ts` that imports `generated/api/fn/<tag>/<op>` and calls it through the generated `Api` service as `this.api.invoke(<op>, params)`, wrapped in `callApi` (`run` in `AuthApi`). `invoke` rejects on an HTTP error, but these services never reject; they return the `HttpOutcome` and `CommandOutcome` unions. `provideApi()` in `app.config.ts` sets the root URL.
3. Add a `SHAPES` entry in `wire.ts` for each new generated model that the PWA converts to a domain type with `fromWire` or `toWire`. Models with no domain type are used as generated.
4. Fix the exhaustive switches in `core/data/command-subject.ts`, `outcome-message.ts` and `pages/inbox/review-copy.ts`.
5. Sending from a screen:
   - Send with `CommandAttempts.send(command)`, which takes the command's key from `keyFor`, sends through `DataStore.send` and settles the attempt. Then show `outcomeMessage(outcome)`.
   - After every await, check `destroyRef.destroyed`.
   - Disable the control while `CommandAttempts.busy(subject)` holds, which is true while a send for the subject is in flight or `awaitingSync()` holds it, and show `<p asys-sync-note>` (`components/atoms/sync-note`) while `awaitingSync()` holds it. `send` raises and lowers the in-flight count itself, so a screen keeps no pending signal of its own. A send that skips `CommandAttempts.send` (the time zone choice) wraps its work in `track(subject, work)`. The subject is the id `commandSubject(command)` returns.
   - A Done goes through `DoneUndo.complete(task, origin)` instead: it holds the Task for the Undo window and owns the key and the send. Quick add goes through `CaptureQueue.submit(text)`. Both are provided by the shell. Quick add's Add is `aria-disabled` while the field is empty, never `disabled`, so a tap never takes focus from the field.
   - A send that waits (on another promise, a timer or a queue) still leaves when the page goes away: on `visibilitychange` to hidden, on `pagehide` and on its owner's destroy it goes out at once through `DataApi.runCommand(command, key, { keepalive: true })`, with the same key and at most once. The run that owns the send performs it, so a `flush()` holding that run waits for exactly this send (see `DoneUndo` in `core/data/done-undo.ts`).
   - There is no offline queue yet, except the in-memory held Done and `CaptureQueue`, which do not survive a reload; that comes in slice 4. Offline, a send fails with "cannot reach the server".

**Palette** (ADR 0013, `libs/design-tokens/README.md`):

1. Add `{ name, accent, highlight, ground }` to `PALETTES` in `scripts/palettes.mts`.
2. Run `node scripts/palettes.mts`. It enforces the contrast pairs (4.5 for text, 3 for lines, 7 for text in drive) and writes the token files and resolver contexts.
3. Add it to `Palette` in `libs/design-tokens/terrazzo.config.mts`, which emits its `[data-palette][data-theme]` blocks; the CSS build fails while a resolver context has none. So that an Area can take it, add it to the domain's `Palette` enum, the `palette` pgEnum in `apps/server/src/db/schema.ts` (with a migration, `adding-an-owned-table`) and the Area editor's options.
4. Update the "12 contexts" count in the design-tokens README, ADR 0013 and `terrazzo.config.mts`.
5. Never hand-edit the generated `palettes/*.tokens.json` or `asys.resolver.json`.

## Tests and checks

- Unit tests use `@angular/build:unit-test` (Vitest, jsdom). Vitest globals are not imported.
- `vi.mock` of relative imports is refused, so override a seam service with `{ provide: X, useValue }`. `pages/now/now.spec.ts` is the model.
- Use the real domain functions over a fixed state and clock.
- Specs that render scripted motion provide a fake `Motion` whose `play` promise they control. The real one resolves at once in jsdom.
- A click handler that must tell Enter or Space from a pointer calls `activationOf(event)` (`components/support/activation`), which returns an `Activation` (`{ keyboard: boolean }`). Never read `event.detail` yourself, and type an output that carries it as `Activation`. A template cannot call an import, so the component exposes it as `protected readonly activationOf = activationOf`.
- `HTMLElement.click()` dispatches a click with `detail: 0`, which `activationOf` reads as keyboard (a Done then moves focus to Undo). A pointer press in a spec dispatches `new MouseEvent('click', { bubbles: true, detail: 1 })`.

```bash
pnpm exec nx run-many -t lint typecheck test build -p pwa
```

```bash
pnpm exec nx format:check --all
```

`typecheck` skips templates, so the `build` (which also checks bundle budgets) and `test` targets are the template check. The plain `nx serve pwa` runs no service worker; try that with `pnpm exec nx run pwa:serve-sw`.
