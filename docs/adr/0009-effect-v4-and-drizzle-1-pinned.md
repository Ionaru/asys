# The server runs on Effect v4 and Drizzle ORM 1.0, pinned to release candidates

The server is built on Effect v4 (HttpApi for the REST API, OpenAPI and the change stream; Layers for the core and its add-ons) with Drizzle ORM 1.0 through its native Effect integration (`drizzle-orm/effect-postgres` on `@effect/sql-pg`), accepting release candidates now to avoid a large migration once both reach stable. Effect reached its stable 4.0.0 on 2026-10-01; Drizzle is still a release candidate. Because both move quickly, versions are pinned exactly with no ranges (`effect`, `@effect/sql-pg`, `@effect/platform-node`, `@effect/platform-node-shared` and `@effect/vitest` at 4.0.0; `drizzle-orm` and `drizzle-kit` at the build `1.0.0-rc.5-5935859`; vitest at 5.0.2, which `@effect/vitest` requires; `pg`, which only `drizzle-kit migrate` uses), one `effect` version is forced across the workspace by a pnpm override (as is `@effect/platform-node-shared`), and CI guards the pairing twice: a type test fails if a Drizzle transaction's error type degrades to `any`, and a runtime smoke test imports `drizzle-orm/effect-postgres`. The two are upgraded together as a planned task, never by a routine install.

## Considered Options

- **Hono 4 with Drizzle 0.45, pg-boss and Zod**: stable today and fully capable, but rejected because it would mean a large migration later.
- **NestJS**: rejected as too heavy on boilerplate.
- **Effect v3 (stable)**: rejected because it guarantees a major migration to v4.

## Consequences

Effect 4.0.0-rc.118 moved `effect/unstable/*` to flat paths (`effect/unstable/httpapi` became `effect/http-api`). Drizzle's runtime code only uses flat paths, but its type files still import `effect/unstable/sql/SqlError`, which would silently become `any`. A `paths` entry in `tsconfig.base.json` maps that specifier to Effect's own SqlError declaration until a Drizzle release imports the new path (drizzle-team/drizzle-orm#6403), and the type test fails if the mapping is removed. Drizzle 1.0.0-rc.4, the last named release candidate, crashes on import under rc.117 because it calls `Schema.TaggedErrorClass`, which Effect removed; the unofficial build `1.0.0-rc.5-5935859` (npm dist-tag `rc5`) fixes that and is used until an official release carries the fix. That crash left the type files looking fine, which is why a runtime smoke test sits next to the type test. `skipLibCheck` is required, since Drizzle's own type files do not compile under strict TypeScript, and it hides both kinds of breakage: an unresolved import in a type file and a runtime call to a removed API. The type test only checks anything when vitest's `typecheck.tsconfig` points at a tsconfig that includes it. Vitest type-checks incrementally, with a build-info file it keeps inside `node_modules`, so after a config change it can replay an old pass; the server's `typecheck` target therefore also runs `tsc --noEmit` on the type test without a cache. Database-backed tests run outside the Nx cache (`--skip-nx-cache`), which hashes files and would replay results after a database-only change. HttpApi only accepts Effect Schema, so the contract package is written in Effect Schema; the domain package stays plain TypeScript with no `effect` import. The trial of this pairing against a real PostgreSQL is recorded in `docs/research/trial-effect-drizzle.md`.
