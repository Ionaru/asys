# Trial: the pinned Effect v4 + Drizzle 1.0 stack (ADR 0009)

On 2026-09-28 the trial named in [ADR 0009](../adr/0009-effect-v4-and-drizzle-1-pinned.md) was run end to end. The stack works, but not as pinned. **drizzle-orm 1.0.0-rc.4 crashes on import under effect 4.0.0-rc.117**, so Drizzle now runs on the unofficial build `1.0.0-rc.5-5935859`. **ADR 0007 as written cannot work**: FORCE ROW LEVEL SECURITY also binds a SECURITY DEFINER function owned by the table owner. **The briefed policy expression raises an error on reused connections.** With those three corrected, every check is green, and each test was seen red for the right reason first. The Nx classic layout, module boundaries, pinned versions, row-level security with a per-transaction owner, and reading a Google Group's members from the work Workspace were all proven against a real PostgreSQL 18 and the real Google APIs.

## Deviations from the brief

1. **drizzle-orm and drizzle-kit are at `1.0.0-rc.5-5935859`, not 1.0.0-rc.4 (your decision).** In rc.4, `effect-core/errors.js` and `cache/core/cache-effect.js` call `Schema.TaggedErrorClass()`, which effect removed in 4.0.0-beta.104; rc.117 only has `Schema.TaggedError`. Upstream, issue #6162 is open and fix PR #6108 was closed unmerged. The rc5 build, published 2026-09-09 under the npm dist-tag `rc5`, uses `TaggedError` and still imports `effect/unstable/sql/SqlError`, so effect stays at rc.117.
2. **The policy uses `nullif(current_setting('app.owner_id', true), '')::uuid` (your decision).** After `set_config(…, true)` commits, the same session reads the placeholder setting as `''`, not NULL, and `''::uuid` raises 22P02.
3. **The lookup function is owned by `asys_lookup`, not `asys_owner` (your decision).** `asys_lookup` is NOLOGIN and BYPASSRLS, owns no tables, and may SELECT only `(id, owner_id)`. The database init script creates it, because only a superuser can grant BYPASSRLS. It also grants it to `asys_owner` `WITH INHERIT FALSE, SET TRUE`, so that migrations can hand functions over. `CREATE` on `public` is granted only for the handover and revoked in the same migration.
4. **`create-nx-workspace` ran with `CLAUDECODE` and `CLAUDE_CODE` unset.** The first run, in Claude Code's environment, ignored the flags (see Surprises). Its output was moved aside and the repository returned to its starting state. Both runs reformatted `docs/research/existing-tools.md` and `docs/scenarios.md` with Prettier; both files were restored from git.
5. **All dependencies are in the root `package.json`, not in `server`.** The classic layout has a single package.json.
6. **Additional pins:**
   - `pg` 8.23.0: `drizzle-kit migrate` needs `pg` or `postgres`. `@effect/sql-pg` has its own wire protocol and no `pg` dependency.
   - vitest and @vitest/coverage-v8 at 5.0.2: @effect/vitest rc.117 requires vitest >=5 <6.
   - an override for `@effect/platform-node-shared`: its rc.118, which already uses the flat paths, would otherwise be picked up through `@effect/platform-node`'s `^4.0.0-rc.117` range.
7. **The pwa has `--unitTestRunner=none`.** Angular 22.1, which @nx/angular 23.2.1 installs, peers vitest ^4.0.8, and one package.json can hold only one vitest. `pnpm peers check` reports the unmet peers of @angular/build and @nx/vitest. Step 2 only asks the pwa to build and lint.
8. **`strict: true` in `apps/server/tsconfig.json`.** Nx's classic `tsconfig.base.json` sets `strict: false`.
9. **`asys_owner` has LOGIN.** Migrations and test f connect as it.
10. **The lookup key is `trial_items.id`**, as `trial_item_owner(item_id uuid) returns uuid`; the table has no other key column.
11. **pnpm 11 build approvals** in `pnpm-workspace.yaml` `allowBuilds`: esbuild, @parcel/watcher, unrs-resolver, lmdb and msgpackr-extract. Without them, installs fail with `ERR_PNPM_IGNORED_BUILDS`.
12. **An extra runtime check, 3b/3c, was added.** The `.d.ts` files are clean, so the type test cannot see the rc.4 crash.
13. **Test setup:**
    - Tests use random owner ids and never truncate. A second layer with one connection (`minConnections: 1`, a long idle timeout) serves b and d.
    - Rejections are asserted as `AuthorizationError` whose PostgreSQL message mentions row-level security, so a 22P02 or a missing grant cannot pass as a rejection.
    - Test c inserts without `RETURNING`. With `RETURNING`, the SELECT policy would reject the row anyway and hide the with-check clause.
14. **Test g matches SqlError by its `_tag` instead of importing it**, so the same file compiles against rc.117 and rc.118. vitest's typecheck uses its own `apps/server/tsconfig.typecheck.json`.
15. **The CLI runs through Node 24's type stripping**, with no separate Nx target. It is still compiled by `nx build server`. Members that are not users are printed with their type, for example `(GROUP)`.
16. **The Google setup wizard lived in the session scratchpad, not the repo.**
17. **`.gitignore` gained `.env`.**

## Surprises

- **create-nx-workspace has an "AI agent mode".** When it sees `CLAUDECODE` or `CLAUDE_CODE` (also OpenCode, Codex, Copilot, Cursor and Gemini variables), it maps `--preset=apps` to the `nrwl/empty-template` template. That template is the TS-solution layout, with `packages:` in `pnpm-workspace.yaml` and nx 23.2.0. The mode also ignores `--aiAgents=none` and writes AGENTS.md, CLAUDE.md, `.claude/settings.json` (enabling an Nx plugin marketplace), `.codex/`, `.cursor/`, `.gemini/`, `.opencode/` and a GitHub CI workflow.
- **Nx replays cached database tests.** The inferred `test` target is cached and hashes only files. With RLS disabled, a cached `nx test server` reported 8 of 8 passing; with `--skip-nx-cache` the same state failed all six database tests.
- **vitest's typecheck checks nothing by default here.** Nx's `apps/server/tsconfig.json` has `"include": []`, so without `typecheck.tsconfig` vitest's tsc passes every type test vacuously.
- **pnpm 11's release-age default is not strict.** An exact pin newer than 24 hours installs anyway, and pnpm silently appends it to `minimumReleaseAgeExclude` in `pnpm-workspace.yaml`. This happened for rc.118 in the scratch copy; the repo file stayed unchanged. `pnpm exec` also prints `Already up to date` on stdout, which breaks JSON output such as `nx show project --json`.
- **pnpm 11's `strictDepBuilds` fails installs on unapproved build scripts.** Nx generators then stop after writing their files. In a non-interactive shell pnpm writes `set this to true or false` placeholders into `allowBuilds`.
- **The forced policy is evaluated inside a SECURITY DEFINER function** owned by the table owner, as the 22P02 raised from inside `trial_item_owner` shows.
- **@effect/sql-pg's `SqlError` message is generic** (`PgConnection: Query failed`); PostgreSQL's message and SQLSTATE sit on `reason.cause`. 42501 maps to `AuthorizationError` and 22P02 to `UnknownError`, and Drizzle wraps the SqlError, inside a `Cause`, in `EffectDrizzleQueryError`.
- **`withOwner(ownerId, effect)` works with the briefed signature.** Queries through the outer `Db` join the transaction because `SqlClient` resolves the connection from the fiber's transaction context. Test d asserts they use the same backend.
- **`Config.Wrap` does not accept raw values.** Every field of `PgClient.layerConfig` must be a `Config`, so the layer reads the URL from `Config` and builds `PgClient.layer` inside `Layer.unwrap`.
- **drizzle-kit 1.0 writes one folder per migration** (`<timestamp>_<name>/migration.sql` plus `snapshot.json`), with no journal. A policy alone makes it emit `ENABLE ROW LEVEL SECURITY`. Changing the policy expression produced a clean `ALTER POLICY`.
- **The PostgreSQL 18 image keeps its data under `/var/lib/postgresql/18/docker`,** so the volume mounts at `/var/lib/postgresql`. The healthcheck must use TCP (`pg_isready -h 127.0.0.1`), because the init server only listens on the socket.
- **Google:**
  - The Console lists `cloud-identity.groups.readonly` as **sensitive**. Your project has no organisation, so the app is External in Testing mode: test sign-ins expire after 7 days, there are at most 100 test users, and production use needs verification.
  - Your Workspace did not block the unverified app.
  - The group's "Who can view members" is "Group members", which let you, as a member, list it.
  - `memberships.list` returns direct members only. Nested groups are listed as members of type GROUP, not expanded.
- **Generator deprecations:** the Angular app generator still emitted the `@nx/eslint:lint` executor (removed in Nx 24; gone since the switch to oxlint), and the vitest config uses `nxViteTsPaths`/`nxCopyAssetsPlugin`, both deprecated for Nx 24.

## Changes to the ADRs

These were proposed by the trial and applied to ADRs 0007, 0009, 0010 and 0012 on 2026-09-29.

**ADR 0007 (owner keys and row-level security)**
- Replace "owned by the table-owning role" with a dedicated lookup role:
  - NOLOGIN, BYPASSRLS, owns no tables, has column-level SELECT on each lookup's key and owner columns only.
  - Created by the database bootstrap (superuser).
  - Granted to the table owner `WITH INHERIT FALSE, SET TRUE`, so migrations can hand functions over.
  - FORCE and SECURITY DEFINER-owned-by-the-table-owner cannot both hold.
  - The membership does not weaken FORCE for the owner. BYPASSRLS is a role attribute, and attributes are never gained through membership, so the owner's own sessions stay filtered (test f) unless they explicitly `SET ROLE` to the lookup role.
  - After the handover, `INHERIT FALSE` leaves the owner no rights over the function. A later `CREATE OR REPLACE`, `ALTER` or `DROP` of a lookup function must `SET ROLE` to the lookup role inside the migration, and replacing one also needs `CREATE` on the schema again.
- Name the one policy expression: `owner_id = nullif(current_setting('app.owner_id', true), '')::uuid`.
- State that the table-owning role is trusted: it can switch FORCE off on its own tables and SET ROLE to the lookup role. RLS guards against the app role and against an accidental owner connection, not against the migration role. That role needs LOGIN.
- Extend "an integration test connected as the app role" with the no-leak test on a single connection, and assert SQLSTATE 42501 rather than any failure.

**ADR 0009 (Effect v4 and Drizzle 1.0 pinned)**
- Pin drizzle-orm and drizzle-kit to `1.0.0-rc.5-5935859` until an official release carries the `TaggedError` fix and still targets `effect/unstable/*`. The pair stays coupled: rc5 still blocks effect rc.118.
- Add a CI runtime smoke import of `drizzle-orm/effect-postgres` next to the type test.
- Require `typecheck.tsconfig` for the type test, or it passes without checking anything.
- Add these exact pins: `@effect/platform-node-shared` (by override), vitest 5.0.2, and `pg` for drizzle-kit.
- Run database-backed tests outside the Nx cache (`--skip-nx-cache`, or `cache: false` on the target).

**ADR 0010 (Nx classic layout)**
- `pnpm-workspace.yaml` holds pnpm 11 settings and must never get a `packages:` key; that key switches later Nx generators to the TS-solution layout.
- Scaffold outside AI-agent environments, or with the agent variables unset.
- Enable `strict` for projects (the classic base sets `strict: false`).
- Decide the vitest split before adding Angular unit tests: vitest 5 (forced by @effect/vitest) against Angular 22.1's vitest ^4. Angular 22.2 accepts vitest 5.
- Linting and formatting: see the follow-up below, which replaces ESLint and Prettier with oxlint and oxfmt.

**ADR 0012 (jobs table)**
- The job-claim function (`FOR UPDATE SKIP LOCKED` across owners) hits the same FORCE and SECURITY DEFINER conflict. It should belong to the lookup role, or a sibling jobs role, holding only the column privileges it needs (SELECT on the due and owner columns, UPDATE on the claim columns). Each job then runs under its owner through `withOwner`.

## Follow-up: oxlint and oxfmt instead of ESLint and Prettier

After the trial, ESLint and Prettier were replaced with oxlint and oxfmt, using the support built into Nx 23.2.1.

**What changed**
- **Removed:**
  - `@nx/eslint/plugin` from `nx.json`, and the pwa's explicit `@nx/eslint:lint` target
  - the four `eslint.config.mjs` files, `.prettierrc` and `.prettierignore`
  - the packages eslint, @eslint/js, typescript-eslint, @typescript-eslint/utils, angular-eslint, eslint-config-prettier, jsonc-eslint-parser, @nx/eslint, @nx/eslint-plugin and prettier
- **Linting:** oxlint 1.85.0 and @nx/oxlint 23.2.1, pinned exactly, set up with `nx g @nx/oxlint:configuration --project=server --plugins=vitest`.
  - Every project gets an inferred, cached `lint` target running `oxlint .`.
  - The root `.oxlintrc.json` enables the `typescript`, `unicorn` and `oxc` plugins, treats correctness rules as errors, and enforces the same module boundaries as before through `@nx/oxlint/boundaries-plugin`.
  - oxlint has no equivalent of the `flat/typescript` and `flat/javascript` presets the ESLint config used (ESLint and typescript-eslint recommended, plus Nx's overrides). Their 20 rules that oxlint implements are listed explicitly in the root config: for example `ban-ts-comment`, `prefer-const`, `no-var`, `no-fallthrough`, `no-empty-function`, and `no-explicit-any` and `no-non-null-assertion` as warnings. The review caught this; the first version enabled only oxlint's correctness category.
  - `apps/server/.oxlintrc.json` extends it with the `vitest` plugin, and tells `vitest/expect-expect` that the type-test helpers `errorTypeOf` and `sqlErrorIn` are assertions.
- **Formatting:** oxfmt 0.70.0, pinned exactly, set up with `nx g @nx/js:init --formatter=oxfmt`.
  - `.oxfmtrc.json` keeps single quotes and ignores `CONTEXT.md`, `docs/`, `pnpm-lock.yaml`, `.angular/` and `apps/server/drizzle/` (drizzle-kit's own output).
  - `nx format` and the Nx generators now format with oxfmt. The code was reformatted once. The changes are line wrapping, because oxfmt's default width is 100 where Prettier's was 80, and key order in `package.json`, because oxfmt's `sortPackageJson` defaults to true.
- **`nx.json`:** the Angular application generator now defaults to `linter: oxlint`. The `production` inputs exclude `.oxlintrc.json` instead of the ESLint configs, so a lint-only change does not invalidate build caches.
- **VS Code:** the recommendations name the Oxc extension instead of the Prettier and ESLint extensions.

**Trade-offs and surprises**
- **Module boundaries now run through an experimental bridge.** Nx labels `@nx/oxlint/boundaries-plugin` experimental, and oxlint's JS plugins are alpha and outside its semver policy. That is why oxlint is pinned exactly: upgrade it as a planned task and repeat the F2 red check each time.
- **ESLint is still installed, indirectly.** `@nx/oxlint` depends on `@nx/eslint-plugin`, whose `@typescript-eslint/utils` peers on eslint, and pnpm's `autoInstallPeers` installs it. It is no longer in `package.json`.
- **Lost with ESLint:**
  - angular-eslint's template and component rules (oxlint does not lint Angular templates)
  - `@nx/dependency-checks`, which linted `package.json` through jsonc-eslint-parser; oxlint lints no JSON
- **Type-aware linting stays off.** `oxlint --type-aware` would need tsgolint, and the ESLint setup had no typed linting either.
- **The newest releases were skipped on purpose.** oxlint 1.86.0 and oxfmt 0.71.0 came out the same day, inside pnpm's 24-hour release-age window, so the week-old 1.85.0 and 0.70.0 were pinned.
- **Nested oxlint configs merge `plugins`.** The schema says `plugins` "will overwrite the base set of plugins", but `oxlint --print-config` shows the server's resolved plugins as `unicorn, typescript, oxc, vitest`, so the `extends` chain keeps the root's plugins.

**ADR 0010**, replacing its ESLint-specific parts (applied on 2026-09-29):
- Module boundaries are enforced by oxlint through `@nx/oxlint/boundaries-plugin`. Pin oxlint exactly and upgrade it deliberately, with the boundaries red check. If the bridge ever breaks, the fallback is ESLint running only `@nx/enforce-module-boundaries`.
- typescript-eslint is no longer a direct dependency. The bridge still loads `@typescript-eslint/utils`, however, so the TypeScript 6 API constraint the ADR names still applies through Nx.
- Formatting is done by oxfmt, with `docs/` and `CONTEXT.md` excluded to keep their hand formatting.

## Further notes from the run

- **Nx flags red-then-green reruns as flaky.** A `--skip-nx-cache` rerun of `server:test` whose earlier run on the same files failed prints "Nx detected a flaky task". Here that is the deliberate red and green, not a flaky database test.
- **Dropping the `vitest/expect-expect` override** in `apps/server/.oxlintrc.json` brings back `error vitest(expect-expect): Test has no assertions` for the two type tests.
- **Relative imports across projects** are rejected by the boundaries rule with its own message: "Projects cannot be imported by a relative or absolute path, and must begin with a npm scope".
- **vitest calls its typecheck mode experimental.** It prints "Breaking changes might not follow SemVer, please pin Vitest's version" on every run, so the exact 5.0.2 pin matters.
- **Unmet peers:** `@angular/build` 22.1.9 wants vitest `^4.0.8`, and `@nx/vitest` 23.2.1 wants `^3.0.0 || ^4.0.0`, against 5.0.2 installed. So `@nx/vitest` also caps vitest at 4; it works with 5 anyway.
- **The pwa production build warns on every run** that the scaffold's `nx-welcome.ts` styles exceed the Angular budget (7.03 kB against 4.00 kB). The warning goes away when the scaffold component is removed.
- **Socket connections skip passwords in the Postgres image.** initdb enables `trust` for local socket connections, so `psql` inside the container without `-h` needs no password; only TCP connections check them.
- **The 22P02 error's detail is on `reason.cause`:** `code: '22P02'`, `routine: 'string_to_uuid'`, and, when it happens inside the lookup, `where: 'SQL function "trial_item_owner" statement 1'`. The reason's `_tag` is `UnknownError` with `operation: 'query'`.
- **The Google CLI's warnings and errors:**
  - Run through type stripping, it triggers Node's `MODULE_TYPELESS_PACKAGE_JSON` warning. Adding `"type": "module"` to the root `package.json` would silence it; that was not done.
  - With Google config missing, it exits 1 with `ConfigError: SchemaError(Expected string at ["GOOGLE_CLIENT_ID"])`.
- **Agent-mode scaffolding also warns** `The "workspaces" field in package.json is not supported by pnpm`, a second sign of the TS-solution template.
- **ESLint 9.39.5 is deprecated.** It stays installed only indirectly, through the boundaries bridge, so pnpm keeps printing that on installs, along with deprecated `glob@10.5.0` and `whatwg-encoding@2.0.0`.
- **Newer versions were already out on 2026-09-28:** Angular 22.2.0, TypeScript 7.0.2 and @types/node 26.6.3. The `@types/node` generated by Nx is ^22, although the runtime is Node 24.
- **`drizzle-kit migrate` names its driver:** it prints "Using 'pg' driver for database querying".
