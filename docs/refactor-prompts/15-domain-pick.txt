Make `pick()` in `libs/domain/src/lib/picker/picker.ts` stop redoing per-call time zone work for every Task, with identical output.

Why: an earlier review measured about 0.23 ms per Task with a Due, about 69 ms for 300 such Tasks on desktop (unverified; a phone is slower). `DataStore.now` in `apps/pwa/src/app/core/data/data-store.ts` (near line 109) reruns `pick` on the main thread on every minute tick, every state change and each Done hold or release, so it may cause jank on Now.

Per Task today: `isUrgentAt` (`task/priority.ts`) calls `addCalendarDays(now, urgencyWindowDays, tz)` whenever the Task has a Latest start. `reasonText` (`picker/reason-text.ts`) and `waitingText` (`picker/waiting-text.ts`) call `formatClock` (`time/display.ts`) or `toLocalDateTime(now, tz)` (`time/zoned.ts`). `isOverdue` (`task/deadlines.ts`) recomputes `dueInstant`. `isWithinActiveHours` (`area/active-hours.ts`) calls `toLocalDateTime(now, tz)` for each Task with an Area. Every one of these runs `isValidTimeZone`, which constructs a `Temporal.ZonedDateTime`, several times per Task.

Change: first measure with a throwaway script (not committed) over 300 Tasks; if it is under about 10 ms, stop and report. Then choose from: (a) memoise `isValidTimeZone` in `time/zoned.ts`, caching valid zones only, because the server (`apps/server/src/owners/create-owner.ts`) and the contract filter (`libs/contract/src/lib/auth.ts`) call it with user input and an unbounded cache of invalid strings would grow; (b) compute the urgency cutoff and the local `now` lazily once per `pick` and pass them to internal variants, keeping every exported signature (the PWA imports `isOverdue`, `formatClock` and `isValidTimeZone`); (c) evaluate Active hours once per Area. Keep the work lazy: today `pick` throws for an invalid zone only when a Task's Due, Available from or known Area needs a conversion, and for an invalid `urgencyWindowDays` only when a ranked Task has a Latest start.

Must stay identical: the `PickResult` for every input, including order, reason texts across DST changes and in zones whose day starts at 01:00, and the errors thrown on invalid input. Before editing, save `JSON.stringify(pick(...))` for a seeded fast-check corpus across zones in the scratchpad, then diff afterwards.

Ask before you start:

- Option (a) only, or also (b) and (c)?
- Is module-level memo state acceptable in `libs/domain`?
