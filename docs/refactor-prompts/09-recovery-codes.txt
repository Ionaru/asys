Extract the shown-once recovery code handling that Sign-up and Account both implement into one shared helper, and decide with me whether to share the markup too.

Why: `features/sign-up/sign-up.ts` and `features/account/account.ts` each keep a `#held` flag around `AppUpdate.hold()` and `release()`, clear `codes` in `#destroyRef.onDestroy`, carry the same `copy()` ('Copied.' and 'Could not copy. Select the codes instead.'), and render the same `<ol class="... asys-num">` plus 'These codes are shown only now. Keep them somewhere safe.' with near-identical list CSS (`.sign-up__codes` in `sign-up.css`, `.account__codes` in `account.css`). A fix to one (a missed release, say) would not reach the other. `account.spec.ts` has five tests, all about sign-out, so Account's half is unpinned.

Current state: Sign-up sets `codes` and `step`, then calls `hold()` before `#session.signedIn()` in `createPasskey`, and releases only on destroy. Account's `makeCodes` holds only `if (!this.#held)`, resets `copyStatus` for each new set, and `hideCodes()` clears, resets and releases through `#releaseHold()`. Layouts differ: Sign-up shows list, sentence, Copy, status, Continue; Account shows list, sentence, Copy and Done side by side, then status.

Resetting the status on `show` is no change for Sign-up, which shows one set.
