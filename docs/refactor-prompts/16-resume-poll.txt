Make `DataStore` ignore a focus or visibilitychange that arrives while a poll started by the other of those two listeners is still in flight, so resuming the app sends one poll instead of two.

Why: returning to the app usually fires `visibilitychange` then `focus`. The first starts `GET /v1/changes`; the second finds `#inFlight`, sets `#followUpPending`, and `#settle()` then starts a second poll at once that can hardly return anything new. That is one redundant request per resume: small, so weigh it against touching a well-pinned state machine. Only `#onFocus` calls `#checkZone`, so there is no second zone check to remove.

Current state: `apps/pwa/src/app/core/data/data-store.ts` has `#onFocus`, `#onOnline` and `#onVisibilityChange`, all calling the private `#trigger()`, which sets `#followUpPending` when `#inFlight`. `#settle()` runs the follow-up when visible or forced. `send` (through `#syncPast`, which sets `#forcedFollowUp`) and `refresh()` deliberately rely on that follow-up.

Change: let the focus and visibilitychange listeners pass a resume marker to `#trigger`. A private flag records that the request in flight was started by such a listener; it is cleared when the request settles and on `stop()`. While it is set, a focus or visibilitychange queues no follow-up. Everything else keeps the generic follow-up: timer polls, `refresh()`, sends, the snapshot from `start()`, and `online`. No new file and no clock.

Must stay identical: a trigger during a timer poll or snapshot queues exactly one follow-up; a focus while hidden is dropped; `visibilitychange` to hidden starts nothing; sends and `refresh()` still queue a follow-up; a 401 and `stop()` drop it; the zone check still runs on every focus.

Ask before you start: (1) Dedupe only focus and visibilitychange against each other (recommended), or also `online`? Ignoring `online` can lose the retry when a resume poll that started offline is still in flight when connectivity returns. (2) Is a flag acceptable, rather than a "started within N ms" window?

Read first: `.agents/skills/building-pwa-ui/SKILL.md` for the layer rules. No ADR governs it.

Tests: `data-store.spec.ts` pins today's rule in `runs exactly one follow-up however many triggers arrived during a poll` (from a timer poll) and `runs exactly one follow-up and one timer for triggers during a poll` (a focus poll then `refresh()`); both must pass unchanged. I found no existing case that fires focus and visibilitychange back to back from idle, so the whole suite should pass; report any that fails as a behaviour change. Add: visible then focus gives one request in total; `refresh()` during a resume poll still queues one follow-up; `online` during a resume poll does whatever decision 1 says; focus during a `refresh()` poll still queues one. Prove the first can fail by removing the flag check.
